01 Quick recap of Lessons 1 & 2

One minute of revision — this lesson stands on these points.

  • ERP = one software, one database, for the whole company. SAP is the leading ERP; FICO = FI + CO is its finance side.
  • Generations: R/3 → ECC → S/4HANA. S/4HANA runs only on the HANA database.
  • SAP is built in three layers: Presentation (your screen) → Application (the brain, runs ABAP programs) → Database (HANA, stores everything). Remember P-A-D.
  • A Client is a separate environment inside one SAP system, identified by 3 digits (for example 100, 800). Client ≠ customer.
  • Work is organised in a landscape: DEV (build) → QAS (test) → PRD (live), and settings travel in Transport Requests.
  • You meet SAP through two faces: the classic SAP GUI and the modern, browser-based Fiori.

Lesson 2 ended at the presentation layer — your screen. This lesson zooms into exactly that layer and stays there: every button, box and message you will touch as a daily SAP user. (Pichle lesson mein hum ne machine ke andar dekha; is lesson mein hum machine ke saamne kharay ho kar usay chalana seekhenge.)

02 What does “Interface” mean?

New word — Interface

An interface is the point where two things meet and talk to each other. In our case: the place where you (the human) meet SAP (the software). Everything you see and touch — the screens, menus, buttons, boxes and messages — together is called the user interface, often shortened to UI.

Analogy — the dashboard of a car

A car's engine does all the real work, but you never touch the engine while driving. You use the dashboard: steering wheel, pedals, gear lever, speedometer and warning lights. The dashboard is the car's interface — it takes your actions to the engine and shows the engine's answers back to you.

SAP is the same. The application server and the HANA database (Lesson 2) are the “engine”. The SAP GUI window and the Fiori screens are the dashboard — and a good driver must know every control and every warning light on it. That is this lesson.

New word — GUI

GUI stands for Graphical User Interface — pronounced “goo-ee”. It simply means an interface you use by looking at pictures, menus and buttons and clicking with a mouse, instead of typing only text commands. Windows, Android and SAP GUI are all GUIs. SAP's classic program is literally named SAP GUI.

One more thing before we start: “interface” is also used in a second, technical sense — a connection between two software systems (for example, a bank sending a file into SAP is an “interface”). That meaning belongs to later, advanced topics. In this lesson, interface = the screens you use.

Memory trick

Interface = “the face between” — inter (between) + face. It is literally the face that stands between you and the system. Jab bhi lafz “interface” aaye, “chehra” yaad kar lein — the face of SAP.

03 The two faces of SAP: GUI and Fiori

You already met both faces in Lessons 1 and 2. Here is the short version again, because this whole lesson walks through both, one by one:

SAP GUI — the classic face

A program installed on your PC. You start it, log on, and work with menus, toolbars and T-codes (short codes for screens). This is where FI consultants do most configuration and heavy daily work even today. Sections 4–13 of this lesson are all about the GUI.

SAP Fiori — the modern face

SAP opened in a web browser — nothing to install. Work is organised as apps shown as tiles on a home page called the Fiori Launchpad. It works on PC, tablet and phone, and it is the face SAP is pushing for S/4HANA. Section 14 tours it.

New word — Frontend / Backend

IT people call the part you see the frontend and the hidden working part the backend. In SAP words: frontend = presentation layer (GUI / Fiori on your device); backend = application layer + database (the servers). When a consultant says “it's a frontend issue”, they mean the problem is on the user's screen side, not in the data.

Important: GUI and Fiori are only two different doors into the same house. Behind both doors stand the same application servers, the same programs and the same HANA database. A document you post in the GUI appears instantly in Fiori, and the other way round — because there is only one data, in Layer 3. (Do darwazay, aik hi ghar — data aik hi jagah rehta hai.)

Exam trap

“Fiori is a different system with its own database” — wrong. Fiori is only an interface (a frontend). Same system, same data. Also beware a third door with a similar name: SAP GUI for HTML (Web GUI) shows the classic GUI screens inside a browser — that is not Fiori. Fiori apps are newly designed apps; Web GUI is the old screens wearing a browser coat.

04 Step 1: SAP Logon — choosing your system

Your SAP day starts here: a small program called SAP Logon, before any accounting screen appears.

New word — Log on / Logon

To log on means to enter a system by proving who you are — with a user name and password. Log off is the opposite: leaving the system properly. The small starting program of SAP GUI is itself called SAP Logon (sometimes “the logon pad”).

When you double-click the SAP Logon icon on your PC, you do not yet see accounting. You see a list of SAP systems you are allowed to enter — because one company has many systems (remember the landscape from Lesson 2: DEV, QAS, PRD — plus training systems). Your IT team (the Basis team — SAP's system administrators) sets up this list for you.

Each line shows a System ID (SID) — the 3-character name of a system from Lesson 2 — plus a short description. As a learner you will normally enter a training or development system. Production (PRD) is the live system with real company data — treat it with respect.

Analogy — doors of a building

The Logon pad is like standing in the street in front of a building with several labelled doors: Office (live work), Workshop (building), Test lab, Classroom. Choosing the door is step 1. Showing your ID card at that door is step 2 — the logon screen, next section.

Exam trap

Do not confuse SAP Logon (the starter program with the system list) with the logon screen (user + password inside one chosen system). Two different steps. Also: the systems in your Logon pad are not different “versions of SAP on your PC” — your PC holds no SAP data at all; the list is just a set of addresses of servers.

After you double-click a system, SAP asks you to prove who you are. The logon screen has just four fields — learn them well, because two of them are favourite exam material:

New word — Session (first meaning)

A session is your one continuous visit inside SAP — from the moment you log on until you log off. Think of it as one “sitting”. Inside one session you can later open several screens at once (Section 10), but it all starts with this single logon. IT people also call one open SAP window a mode — same thing.

What if you are already logged on somewhere else?

If your user ID is already logged on (for example, you left yourself logged on at another PC), SAP shows a warning box with three choices: continue and end the other logon, continue without ending it (multiple logons are recorded and can cost an extra licence), or cancel this logon. Choose calmly — it is not an error, just SAP keeping count. (Ghabrana nahi — ye sirf aik warning hai, ghalti nahi.)

Memory trick — “C-U-P-L”

The 4 logon fields in order: Client, User, Password, Language — “Cup of tea, please, with Lemon”? Simpler: “Chai Usko Pilao, Lemon ke saath” — Client, User, Password, Language. If an exam question asks what the logon screen needs, CUP-L is the complete answer.

Exam trap — Enter is not Save

New users press Enter and think the document is saved. Wrong. Enter only sends the screen for checking/continuing. Data is saved only with Save (Ctrl+S) — or, in FI, by posting. A classic beginner (and exam) confusion: Back (F3) vs Exit (Shift+F3) vs Cancel (F12) are three different ways of leaving — Back keeps you one step inside, Exit leaves the transaction, Cancel throws away unsaved typing.

You can open any transaction by double-clicking its line in the tree. That is the slow, safe, learning way — good for your first weeks. The fast way, used by every experienced user, is typing the transaction's T-code in the command field — the next section.

New word — Menu path

A menu path is the written route through the folders, like a postal address: SAP Menu → Accounting → Financial Accounting → General Ledger → Document Entry → FB50 – Enter G/L Account Document. Books and exam questions often give the menu path; the T-code is its shortcut.

Memory trick — see the T-codes inside the tree

In Easy Access, open menu Extras → Settings and tick “Display technical names”. Now every line of the tree also shows its T-code next to the name. This one setting turns the menu tree into your personal T-code teacher — leave it on while you learn. (Ye aik setting poori menu ko aap ka ustaad bana deti hai.)

08 T-codes and the command field — the fast way

New word — Transaction / T-code

In SAP language, a transaction is one task-screen — one job you open and complete, like “post a G/L document” or “display a vendor”. (It is not the accounting meaning of transaction!) Every transaction has a short code, its transaction code or T-code: 1–20 characters, usually 4–6, like FB50, FS10N, SU3. Typing a T-code in the command field and pressing Enter jumps you straight to that screen.

New word — Command field (OK-code field)

The command field is the small white box at the left of the standard toolbar — in old SAP documents it is called the OK-code field. It is SAP's “address bar”: whatever code you type there, SAP takes you to it. If it is hidden, click the small arrow at the toolbar's left edge to open it.

T-codes have a pattern — learn to read them

  • The letters usually hint at the area. In FI you will constantly meet F-codes: FB… document posting, FS… G/L accounts, FK… vendors (Kreditoren — German for creditors!), FD… customers (Debitoren), OB… configuration steps. SAP was born in Germany, so some letters are German — do not fight it, just learn the famous ones.
  • The ending 01 / 02 / 03 trick: for master data, …01 = Create, …02 = Change, …03 = Display. Example: FK01 create vendor, FK02 change vendor, FK03 display vendor. Same music for customers: FD01 / FD02 / FD03, and G/L accounts: FS00 is the central all-in-one screen.
  • “Enjoy” transactions: newer, friendlier single screens often carry a 50-series or plain name — FB50 (post G/L document, one screen) is the “enjoy” version of the classic two-screen F-02. You will use both in later lessons.

Analogy — phone contacts vs dialling numbers

Walking the menu tree is like opening your phone's contact list and scrolling to a name. Typing a T-code is like dialling the number directly because you know it by heart. Beginners scroll; professionals dial. Your job in this course: slowly memorise the 20–30 numbers of FI daily life.

Exam trap

A T-code does not give you permission by itself. Knowing SPRO does not mean you may configure — your user needs the matching authorisation (permission given by the security team). SAP checks your rights every time you start a transaction; “No authorisation” is a normal message, not a system fault. Also: SE93 displays/defines transaction codes — it is not where you “search the menu”; for that, use the menu search in Easy Access (Section 7) or SE93's own search help.

Memory trick — read the letters

/n = New transaction here (ends the old one). /o = Open another window. /nex = N + Exit — the full exit. And the difference that matters most: /nTCODE replaces, /oTCODE adds. Urdu mein: “/n badal deta hai, /o barha deta hai.”

Exam trap

Two favourites: (1) “/nex asks for confirmation before logging off” — wrong, that is exactly what it skips; the normal logoff (System → Log Off) asks. (2) “/o logs you off and on again” — wrong, it only opens another session under the same logon. No new password, no new logon.

10 Many screens at once: sessions (modes)

Real accounting work is never one screen at a time. You are posting a document, but you must check an account balance; you check the balance, but you must see the vendor's master data. SAP's answer: under one logon you may open up to 6 sessions (windows) in parallel — the standard default.

Three ways to open a new session

  • Type /o + T-code in the command field, e.g. /oFS10N.
  • Click the “Create new session” button on the standard toolbar.
  • Menu System → Create Session.

Each new session opens at the Easy Access screen unless you gave a T-code with /o. Your status bar quietly tells you which session number you are in (Section 11).

Analogy — one desk, many open registers

A manual accountant keeps several registers open on one desk — cash book here, ledger there — and flips between them while staying the same person at the same desk. Sessions are exactly that: one desk (one logon), up to six open registers (sessions). Logging off is leaving the desk; /i is closing just one register.

Exam trap

(1) A new session is not a new logon and needs no password again. (2) The standard maximum is 6 sessions per logon — a very quotable number. (3) If two of your sessions try to edit the same record at the same time, SAP's lock (the Enqueue from Lesson 2) will stop the second one — even against yourself! Display in one window, edit in the other.

11 The status bar and message types: S – I – W – E – A – X

SAP talks to you all day through one thin line at the bottom of the window. Learn its language and you will always know: did my work save? Is this a small warning or a full stop?

What the status bar shows

  • Messages — on the left: the system's answers (“Document 100000123 was posted”, “Enter a company code”…).
  • System information — on the right: which system, client, user and session you are in. Clicking this area opens a small info panel. When something looks wrong, check here first: half of all “SAP is broken!” cries are simply a user working in the wrong client.
  • Double-click a message in the status bar to open its long text — a fuller explanation, often with the fix written inside.

The six message types — the heart of this lesson

TypeNameSimple meaningWhat you do
SSuccess“Done!” Shown quietly in the status bar, usually green. Example: “Document 100000123 was posted in company code 1000.”Nothing — note the document number and carry on. This is the message every accountant waits for.
IInformation“Just telling you.” Appears as a pop-up box you must confirm.Read it, press Enter, continue. No damage, no stop.
WWarning“Careful — this looks unusual, but it may be allowed.” Usually yellow, in the status bar.Read it properly. Often you may press Enter to accept and continue — but a warning means SAP noticed something; do not Enter blindly.

New word — Short dump

A short dump is SAP's crash report: when a program hits a problem it cannot survive, SAP stops it and writes a technical report (what program, what line, what data). Users just see “the screen died with a dump”. Remember only this: X-type = program crash = technical team's job, and the analysis T-code is ST22.

Memory trick — traffic lights + two endings

S = Sabz (green) — success, go. W = Warning — yellow, slow down, look, then go. E = Error — red, full stop, fix it. I = Information — just a notice board. Then the two rare endings: A = Abort (transaction ends politely) and X = eXit/crash (program dies). Order yaad rakhein: “S-I-W-E-A-X — pehle teen roz ke, aakhri do ghair-mamooli.”

Exam trap

(1) A warning (W) does not always block you — in many screens Enter accepts it; an error (E) always blocks. Exam questions love this difference. (2) Success messages appear in the status bar, information messages as a dialog pop-up — swapping these two is a classic wrong option. (3) Whether a business check gives a W or an E is often a setting (message control in configuration) — the same check can be a warning in one company and an error in another.

12 F1 and F4 — your two lifesaver keys

If you remember only two keys from this whole lesson, remember these. They turn every SAP field into its own teacher.

F1 — Help for this field (“What is this?”)

Click inside any field and press F1. SAP opens the Performance Assistant window explaining: what this field means, what values it expects, and often links to deeper documentation. Technical people also use F1's “Technical Information” to learn the field's table and field name — your first bridge to the database of Lesson 2.

Use it when: you do not understand a field. Before asking anyone — F1.

F4 — Possible values (“What can I enter?”)

Click inside a field and press F4. SAP opens a search help: a list/search window of the allowed values for that field — all company codes, all G/L accounts, all vendors. Pick one with a double-click and SAP fills the field for you. Fields that offer F4 show a small dropdown icon when you click into them.

Use it when: you do not know the exact code/number. Never guess codes — F4.

New words — Search help / Matchcode

The F4 list is called a search help. Old SAP books call it a matchcode — same idea, older word: a helper that finds records by part of the name. In a search help you can type part of a name with stars, e.g. *textile*, to find “every vendor whose name contains textile”. The star * means “anything can stand here” — SAP's wildcard.

Analogy — asking the shopkeeper

F1 is asking: “What is this thing?” — the shopkeeper explains the product. F4 is asking: “Show me all the ones you have.” — the shopkeeper brings the full tray to choose from. Explanation vs list: F1 explains, F4 lists. (F1 samjhata hai, F4 dikhata hai.)

Three more everyday keys

KeyNameUse
F3 / Shift+F3 / F12Back / Exit / CancelThe three ways of leaving a screen (Section 6). Learn them as a family.
Ctrl + Page Up/Down, Page Up/DownScrollingMove through long lists and reports page by page; the toolbar also has first/previous/next/last page buttons.

Exam trap

“F4 gives the explanation of a field” — wrong, that is F1. “F1 lists the allowed values” — wrong, that is F4. The exam swaps them on purpose. Lock it in: F1 = information about the field; F4 = values for the field. One more: F1 help exists for fields and for messages — put the cursor on a status-bar message and press F1 to get its long explanation too.

13 Make SAP yours: favourites and your own defaults

SAP starts the same for everyone, but within a week your SAP should look like your SAP. Three tools do that.

1. Favourites — your own shortcut folder

At the top of the Easy Access tree sits Favourites. Anything you use daily — transactions, reports, even web links — can live here, in folders you name yourself (“Daily Posting”, “Month-End”).

  • Add: in the menu tree, right-click a transaction → Add to Favourites (or menu Favourites → Add, or simply drag & drop it into the Favourites folder).
  • Organise: right-click the Favourites folder → create sub-folders, rename, move up/down.
  • Remove: right-click the entry → Delete Favourite. Deleting a favourite deletes only the shortcut — never the transaction itself.

2. SU3 — your personal defaults

T-code SU3 (Maintain User Profile) is where you set things SAP should remember about you:

SU3 tabWhat you set there
AddressYour name and contact data as shown inside SAP.
DefaultsLogon language, date format (DD.MM.YYYY etc.), decimal notation (1,234.56 or 1.234,56), your printer, and a start transaction — the screen you land on after logon instead of Easy Access.
ParametersUser parameters: standing values SAP pre-fills for you everywhere — the most famous is parameter BUK = your usual company code. Set BUK once, and company-code fields across SAP arrive pre-filled with your company.
New word — User parameter (Set/Get parameter)

A user parameter is a small named memory SAP keeps for your user ID — like a sticky note saying “this person's company code is 1000”. Technically it works as a Set/Get parameter: screens get the value to pre-fill a field, and some screens set it when you choose a value. The 3-letter parameter ID (BUK, etc.) is its name. You will meet more of these in later lessons.

3. Hold Data / Set Data — inside one transaction

Inside many entry screens, the menu System → User Profile offers Hold Data and Set Data:

  • Hold Data — the values you typed on this screen are kept and shown again next time you open the screen in this session; they disappear when you log off.
  • Set Data — stronger: the values are kept permanently (also after logoff) and the fields become non-editable pre-filled values until you choose Delete Data.
Analogy — three kinds of memory

Hold Data is a pencil note on today's page — gone tomorrow. Set Data is printing your name on the register cover — stays until you change it. SU3 parameters are your registered signature at the bank — SAP applies them everywhere, on every screen, automatically.

Exam trap

(1) SU3 changes only your own profile; changing other users is SU01 (user administration — an admin/security job, not yours). (2) Favourites are personal — your favourites list is not shared with colleagues, and it is not configuration; nothing in Favourites is ever transported. (3) A start transaction in SU3 does not remove Easy Access — /n still takes you home.

14 Tour: the Fiori Launchpad — SAP's modern face

Now the second door. You open a browser, go to the Fiori address your company gives you, and log on with the same user and password. No installation, no SAP Logon pad.

New words — Launchpad, Tile, App, Space & Page

The Fiori Launchpad is the Fiori home page — the starting point of all Fiori work. Work is offered as apps: small, focused programs (“Post Outgoing Payments”, “Manage Journal Entries”), each shown as a square card called a tile. Tiles are organised into spaces (big work areas, like “Finance”) containing pages (groups of related tiles). Older systems organise tiles into catalogs and groups — same idea, older words.

Parts of the Launchpad

  • Shell bar (top strip): the space/page menu on the left, a search box in the middle (search apps — and in many setups also business objects like a vendor name), and on the right the notifications bell and your user menu (settings, App Finder, log off).
  • Tiles: one click opens the app. Some tiles are smart: they show a live KPI number or mini-chart directly on the tile.
  • App Finder: from the user menu — a searchable catalogue of every app your role allows, for finding apps not pinned on your pages.
  • Role-based: you only see the apps of your job. The AP clerk's Launchpad and the chief accountant's Launchpad look different — SAP shows each person their own work. (Har shakhs ko sirf apna kaam dikhta hai.)
New word — Role

A role is a bundle of permissions matching one job (“Accounts Payable Accountant”). Roles decide both which Fiori apps appear on your Launchpad and which T-codes you may start in the GUI. One person can hold several roles. If an app or T-code is missing, it is almost always a role/authorisation matter — not a broken system.

Analogy — phone home screen

The Launchpad is your phone's home screen; tiles are app icons; spaces and pages are home-screen pages/folders; the App Finder is the app drawer; the search bar is the swipe-down search. If you can use a smartphone, you already understand Fiori's design — that is exactly why SAP built it this way.

16 Exam traps for Lesson 3

The wrong options in C_TS4FI are usually one of these. Read them slowly — each one has caught real candidates.

  • Enter ≠ Save. Enter checks/continues; only Save (Ctrl+S) or posting stores data.
  • Message types: S = success (status bar), I = information (pop-up dialog), W = warning (can often be accepted with Enter), E = error (must correct), A = abort (transaction ends), X = exit/short dump (program crash, see ST22).
  • F1 vs F4: F1 = explanation of the field; F4 = list of allowed values (search help). The exam swaps them deliberately.
  • /n vs /o: /nTCODE replaces the transaction in the same window; /oTCODE opens a new window. /nex logs off without confirmation.
  • Sessions: maximum 6 sessions under one logon; a new session needs no new logon and no password.
  • Logon screen = 4 fields: Client, User, Password, Language. Company code is not a logon field — you choose it inside transactions (or default it with parameter BUK).
  • Back / Exit / Cancel: F3 = back one screen; Shift+F3 = exit the transaction; F12 = cancel without saving.
  • GUI vs Fiori data: both interfaces use the same backend and database. Fiori is not a separate system, and Fiori did not delete the GUI.
  • Web GUI ≠ Fiori: classic screens rendered in a browser are GUI for HTML, not Fiori apps.
  • Standard vs application toolbar: the standard toolbar is identical on all screens; the application toolbar belongs to the current transaction only.
  • SU3 vs SU01: SU3 = your own profile/defaults; SU01 = administering other users (admin job).
  • T-code ≠ authorisation: knowing a code never grants the right to run it; roles/authorisations decide.

18 Summary — key points for C_TS4FI

  • Interface = the face between you and SAP. The two faces of S/4HANA are SAP GUI (installed, T-codes) and Fiori (browser, tiles) — both over the same backend and HANA database.
  • Starting work is two steps: SAP Logon (choose the system) → logon screen (Client, User, Password, Language).
  • Every GUI screen has the same skeleton: title bar, menu bar, standard toolbar + command field, application toolbar, screen body, status bar.
  • SAP Easy Access is the GUI home screen: menu tree + your personal Favourites. Turn on Extras → Settings → Display technical names to see T-codes in the tree.
  • A transaction is one task-screen; its T-code typed in the command field is the fast way in. Endings 01/02/03 = create/change/display.
  • Slash-commands: /n end transaction, /nTCODE replace, /oTCODE new window, /i close this session, /nex log off without asking.
  • One logon can hold up to 6 sessions in parallel — no extra password.
  • Messages: S success · I information · W warning · E error · A abort · X exit/dump. Double-click a status-bar message for its long text.
  • F1 explains a field; F4 lists its allowed values. Never guess a code — F4 it.
  • SU3 holds your personal defaults and parameters (e.g. BUK company code); Hold/Set Data makes entry screens remember your values.
  • Fiori: Launchpad → spaces → pages → tiles → apps, all filtered by your role; the App Finder lists everything your role allows.
  • Useful T-codes of this lesson: SU3 your defaults, SE93 transaction codes, SM04 user sessions, ST22 short dumps, SPRO configuration.
