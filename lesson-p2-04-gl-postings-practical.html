01 Where the course stands — from building to posting

Everything so far was preparation. Today the preparation starts earning its keep.

Look back at what you already know. In Part 1 you built the enterprise structure (company, company code), the chart of accounts, the fiscal year and posting period rules, retained earnings, ledgers and document types. In Part 2 · Lessons 1–2 you repeated all of that practically — searching company details, setting account series and lengths, creating unique codes, and assigning the Posting Period Variant and retained earnings account. In Part 2 · Lesson 3 you learned to read: reports, line items in FBL3N, documents in FB03, and table queries in SE16N.

One thing is still missing: nothing has actually been posted by you yet. A chart of accounts with no entries is like a cash book with blank pages. This lesson fills the pages. Here is the complete map of today’s work:

JobQuestion it answersMain tools
1 · Prepare the account“Does this G/L account exist for my company code, and is it set up correctly for posting?”FS00
2 · Post the entry“Record this transaction — debit one account, credit another.”FB50 · F-02
3 · Check the entry“Show me exactly what was posted, and let me fix small mistakes.”FB03 · FB02
4 · Undo the entry“This posting is wrong — cancel it in a legal, traceable way.”FB08
5 · Pause the entry“I am not finished / not sure — save my work without posting it.”Park (FV50 · FBV0) · Hold (FB50)
Analogy · Khata khul gaya, ab entry hogi

Ab tak aap ne khata (ledger book) banaya — pages numbered (chart of accounts), har page par heading (account names), aur dukaan ke khulne ke timings (posting periods). Aaj pehli dafa us khate mein entry likhenge: karaya (rent) diya to Rent page par debit, Cash/Bank page par credit. Aur agar ghalti ho jaye to page phaar nahi sakte — qanoon kehta hai ke ek nayi ulti entry (reversal) karke ghalti ko neutralize karo, taake record hamesha saaf aur traceable rahe.

Key term · Posting

A posting is the act of saving a balanced accounting entry into SAP so that it becomes part of the official books. Before you press Post, your entry is just typing on a screen — it affects nothing. The moment SAP accepts it, it receives a document number, lands in the Universal Journal (ACDOCA), changes account balances, and can never be deleted — only reversed. Posting matlab entry ko pakka kar dena — jaise pen se likhi hui entry; pencil wali draft nahi.

02 The G/L account master — what an account really is

You cannot post to an account that does not exist — and “exists” in SAP means two separate things.

In your paper accounting, a ledger account is just a page with a name: “Rent Expense”, “Bank”, “Capital”. In SAP a G/L account is a master record — a stored definition that controls how the account behaves every time someone posts to it. That master record has two segments, and you met both in Part 1:

The fields that control posting Exam favourite

FieldWhereWhat it controls, in simple words
Account typeChart segmentThe account’s family: A Assets, D Customers, K Vendors, M Materials, S G/L accounts. A pure G/L account like Rent or Bank carries type S.
Account groupChart segmentControls the number range the account number must fall in (the series you set in Part 2) and which fields are required / optional / hidden when the master is created — its field status.
P&L statement account / Balance Sheet accountChart segmentOne radio choice: is this an income/expense account (P&L) or an asset/liability/equity account (Balance Sheet)? P&L accounts need the retained earnings assignment (OB53) to work at year end.
Field Status GroupCompany code segmentDecides which extra fields appear — and which are compulsory — when someone posts to this account. Example: an expense account’s group can force a cost centre on every posting.
Line Item DisplayCompany code segmentA tick box. If ON, you can see every individual entry of this account in FBL3N. If OFF, only totals are stored for display. Almost all real accounts keep it ON.
Open Item ManagementCompany code segmentA tick box. If ON, every entry stays “open” until it is matched (cleared) with an opposite entry — used for clearing accounts like bank clearing or GR/IR. Expense and revenue accounts normally keep it OFF.
Tax categoryCompany code segmentTells SAP whether postings to this account may / must carry a tax code (input tax, output tax, or “posting without tax allowed”).
Key terms · Master data vs transaction data

Master data is the long-lived “definition” data — G/L accounts, vendors, customers. It changes rarely. Transaction data is the day-to-day movement recorded against that master data — your postings. FS00 maintains master data; FB50 creates transaction data. Master data = dukaan ke shelf aur un par lage label; transaction data = roz ka sauda jo un shelves par hota hai.

Memory trick · “SKA pehle, SKB baad mein”

SKA1 = chart segment — the account’s identity (one per chart). SKB1 = company code segment — the account’s permission to work in one company code. Identity first, permission second — jaise pehle CNIC banta hai (SKA1), phir kisi sheher mein job ki permission milti hai (SKB1).

03 Step by step — FS00: display, create & extend a G/L account

FS00 is the one screen where G/L accounts are displayed, created, changed and extended — centrally, for chart and company code together.

Key term · FS00 — Central G/L account maintenance

FS00 maintains a G/L account centrally: both segments (chart + company code) in one transaction. Older separate transactions exist — FSP0 (chart segment only), FSS0 (company code segment only) — but FS00 is the everyday tool and the exam’s default answer. FS00 aik hi counter hai jahan account ki dono files — chart wali aur company code wali — aik saath khulti hain.

Task A — Display an account before you post to it

  1. Type FS00 in the command field and press Enter.
  2. Enter the G/L account number (for example 630100 — Office Rent) and the company code (for example PK01).
  3. Press the Display (glasses) icon — or simply press Enter — to open the account in display mode.
  4. Read the three tabs: Type/Description (account type, account group, P&L or Balance Sheet choice, names), Control Data (currency, tax category, line item display, open item management), Create/Bank/Interest (field status group, and house-bank details where relevant).
  5. Check the two things that decide whether your posting will work: Line Item Display is ticked, and the Field Status Group matches the account’s job (an expense account should demand a cost centre).

Task B — Create a brand-new account

  1. In FS00, enter the new account number — it must fall inside a number range of an account group in your chart (remember the series from Part 2: e.g. expenses 600000–699999) — plus the company code.
  2. Press the Create (blank page) icon. SAP may offer “with template”: copying an existing similar account and changing its name is the fastest safe route.
  3. Fill the Type/Description tab: account group, P&L or Balance Sheet choice, short text and long text.
  4. Fill the Control Data tab: currency, tax category, tick Line Item Display; tick Open Item Management only for clearing-type accounts.
  5. Fill the Create/Bank/Interest tab: the Field Status Group.
  6. Save (Ctrl+S). The account now exists in SKA1 and SKB1 together — it can be posted immediately.

Task C — Extend an existing account to another company code

“Extend” means: the chart segment already exists, and you create only the missing company code segment. In FS00, enter the account number and the new company code, press Create, fill the company-code tabs (Control Data, Create/Bank/Interest) and save. The Type/Description data is already there from the chart segment.

Exam trap · “Account does not exist in company code”

If FB50 later refuses with “Account 630100 does not exist in company code PK02”, the chart segment exists but the company code segment is missing for PK02. The fix is Task C in FS00 — not creating a new account number. Exam questions love this exact error.

04 Anatomy of a posting — header, line items, debits & credits

Every SAP posting — whether from FB50, an invoice, or payroll — is stored as one document with the same skeleton.

You already know double-entry bookkeeping: every transaction touches at least two accounts, total debits equal total credits. SAP stores exactly that, in a fixed shape called a document:

The header fields you will type every day

FieldSimple meaningWhy it matters
Document dateThe date printed on the source paper (invoice / voucher date).Evidence of when the business event happened.
Posting dateThe date on which the entry counts in the books.Decides the posting period and fiscal year — and the period must be open (OB52), otherwise posting is refused.
Document typeA two-letter code (e.g. SA) classifying the entry.Controls the number range and which account types may be used — Section 5.
ReferenceThe external paper’s number (supplier invoice no., cheque no.).Your bridge back to the physical document.
Header textA short free-text note for the whole document.Future readers thank you. Auditors too.

And each line item carries…

  • G/L account — which page of the ledger this line hits.
  • Debit / Credit indicator — in classic screens shown as posting key or an S/H flag (S = Soll = debit, H = Haben = credit, from German).
  • Amount — in document currency.
  • Text — a line-level note (“Rent – November”).
  • Extra assignments demanded by the field status group — most often cost centre for expense lines, sometimes profit centre, assignment, or tax code.
Key term · Cost centre

A cost centre is a label for where inside the company a cost belongs — a department, branch or shop floor. It is not an account; it is an extra tag on the posting line so management can ask “how much did the Faisalabad office spend on rent?” Account batata hai kharcha kis cheez par hua; cost centre batata hai kis department ne kiya.

05 Posting keys & document types — the two control codes

Two small codes quietly control every posting. Learn them once; they appear in almost every C_TS4FI question paper.

Posting keys — one per line item Memorise the G/L pair

A posting key is a two-digit code attached to each line item. It answers three questions at once: is this line a debit or credit, what kind of account it hits, and which fields the line will ask for.

Posting keyMeaningUsed for
40Debit to a G/L accountExpense / asset lines in a manual G/L posting
50Credit to a G/L accountBank / liability / income lines in a manual G/L posting
31Credit to a vendorVendor invoice (accounts payable)
21Debit to a vendorVendor payment / debit memo side
01Debit to a customerCustomer invoice (accounts receivable)
11Credit to a customerCustomer payment / credit memo side

In FB50 you never type posting keys — you choose Debit or Credit in a column and SAP fills the key (40/50) behind the scenes. In F-02 you type the keys yourself. That single difference explains most of the FB50 vs F-02 story in Section 9.

Document types — one per document

A document type is a two-letter code on the header (defined in OBA7, from Part 1 · Lesson 9). It classifies the whole entry and controls its number range and permitted account types.

TypeStands forTypical use
SAG/L account documentGeneral manual G/L postings — FB50 and F-02 default
KRVendor invoiceAccounts payable invoices
KZVendor paymentPaying a vendor
DRCustomer invoiceAccounts receivable invoices
DZCustomer paymentReceiving from a customer
ABAccounting document (general)Also used as the standard reversal document type
Memory tricks · 40/50 and SA

“Chaar-sau Debit, Pachaas Credit” — 40 ki awaz mein “D” chhupa hai: 40 = Debit, 50 = Credit. Ulta yaad karne ki ghalti sab se aam hai — is jumle ko ratta laga lein. Aur SA = “S”ab ka “A”am — the general, everyday G/L document type.

06 Step by step — FB50: your first G/L posting

FB50 is the “Enjoy” posting screen: header on top, all lines in one table, debit and credit totals shown live. This is where beginners — and most accountants — post.

Key term · Enjoy transaction

Enjoy transactions are SAP’s friendlier, single-screen versions of older multi-screen transactions. FB50 is the Enjoy version of G/L posting: everything visible at once, no posting keys to memorise, and a traffic-light balance indicator. Enjoy screen matlab aik hi screen par poora kaam — purani screens ki tarah har line ke liye alag page nahi khulta.

  1. Type FB50 and press Enter. If SAP asks, confirm the company code (PK01) — FB50 remembers the last one used.
  2. Fill the header: Document date, Posting date, Document type SA, Reference, and a short Header text.
  3. In the line table, enter line 1: G/L account, choose D (Debit) in the D/C column, amount, text, and the cost centre if the field status group asks for it.
  4. Enter line 2: G/L account, C (Credit), amount, text.
  5. Watch the balance light at the top: red while debits ≠ credits, green when the difference is zero. SAP will not post a red document.
  6. (Recommended habit) Press Simulate first — SAP shows the exact document it is about to save, so you can catch a wrong account before it becomes permanent.
  7. Press Post (Ctrl+S). SAP replies: “Document 100000123 was posted in company code PK01” — note that number; it is your proof and your search key for FB03.

Key term · Simulate

Simulate means “show me the final document exactly as it would be saved — but save nothing yet.” It is a free rehearsal: wrong account, wrong side, missing cost centre — all visible with zero consequences. Professionals simulate before every non-routine posting. Simulate = dress rehearsal; asal performance (posting) us ke baad.

07 Worked example — office rent, posted end to end

One complete story, from paper voucher to document number — the exact rhythm you will repeat thousands of times in a real job.

The business event: On 5 November 2026, Ibrahim Apparel & Trading (company code PK01) pays the November office rent of PKR 50,000 by cheque from its bank account. The cheque number is 8841. In plain accounting you already know the journal:

Journal (manual book) → SAP document · ILLUSTRATION
Rent Expense A/c ............ Dr 50,000 To Bank A/c ................... 50,000 (Being office rent for November 2026 paid by cheque 8841) ────────────────────────────────────────────────────────────── In SAP (FB50, type SA): Line 1 630100 Office Rent D 50,000.00 Cost centre PK-ADMIN Line 2 110100 Bank – Main C 50,000.00 Result: Document 100000123 posted in company code PK01, fiscal year 2026, period 11

What just happened inside SAP — follow the chain

  1. Period check: posting date 05.11.2026 → period 11 of fiscal year 2026. SAP checked OB52: period 11 is open for account type S and for document type SA’s range — posting allowed.
  2. Master checks: both accounts exist in PK01 (SKB1), rent account’s field status group G004 demanded a cost centre — supplied (PK-ADMIN).
  3. Balance check: debit 50,000 = credit 50,000. Green light.
  4. Number assignment: document type SA drew the next free number from its number range: 100000123.
  5. Storage: header saved in BKPF; two line items saved in ACDOCA — one row per line, carrying account, amount, cost centre, posting date and the document key (100000123 + PK01 + 2026).
  6. Balances updated: Rent Expense now shows +50,000 debit in FBL3N and in the trial balance; Bank shows −50,000. The Lesson 3 reports read exactly these rows.
Analogy · Entry ke baad khata khud bolta hai

Manual system mein entry likhne ke baad aap ko khud total karna parta tha. SAP mein entry post hote hi har report khud update ho jati hai — kyun ke report koi alag register nahi, wohi ACDOCA wali rows ka jama (sum) hai. Isi liye Lesson 3 mein kaha tha: total ajeeb lage to drill-down karke usi document tak pahuncho jo aap ne abhi banaya.

08 Step by step — F-02: the classic posting screen

F-02 is the original SAP posting screen: one line at a time, driven by posting keys. Older consultants still swear by it — and the exam still asks about it.

The biggest mental shift: in F-02 you do not fill a table. You enter a header, then you describe the first line (account + posting key), press Enter, fill that line’s amount on the next screen, and immediately describe the next line on the same screen. Line by line, like a conversation with SAP.

  1. Type F-02 and press Enter.
  2. Fill the header: document date, posting date, type SA, company code PK01, currency PKR, reference.
  3. At the bottom, in the “First line item” area: Posting key 40 (debit G/L), Account 630100. Press Enter.
  4. The item screen opens: enter Amount 50,000, Text, and Cost centre PK-ADMIN. At the bottom, in “Next line item”: Posting key 50 (credit G/L), Account 110100. Press Enter.
  5. Enter the credit line’s Amount 50,000 and Text. Leave the “Next line item” area empty this time and press Enter — or open the menu Document → Simulate to see the complete document.
  6. Check the simulated document (debit = credit), then Post (Ctrl+S). SAP issues the document number, exactly as in FB50.

F-02 mein har line ka apna page khulta hai — “aik waqt mein aik line”. Agar interview ya exam mein poochha jaye “posting keys kahan type hote hain?” — jawab hamesha F-02 (aur doosri classic F- screens), FB50 nahi.

09 FB50 vs F-02 — which screen, when?

Both create exactly the same document in the same tables. Only the driving experience differs.

PointFB50 (Enjoy)F-02 (Classic)
LayoutSingle screen: header + all lines in one tableHeader screen, then one screen per line item
Debit / CreditChoose D or C in a columnType the posting key (40 / 50 …)
Balance checkLive traffic light while typingVisible in Simulate / document overview
Account typesG/L accounts onlyG/L, vendor and customer lines (keys 31, 01 …) in one document
ExtrasTree / screen variants, hold document, fast entry templatesSupports special G/L indicators and classic cross-company flows
ResultIdentical: one document in BKPF + ACDOCA, type SA by default, next number from the same range

Practical rule: pure G/L entries (rent, salaries accrual, depreciation adjustments) → FB50, because it is faster and safer. Entries mixing vendors/customers, or when a senior insists on posting keys → F-02 family. In Fiori, the app “Post General Journal Entries” is the modern face of the same FB50 idea — same document, same checks.

Exam trap · FB50 cannot post to vendors/customers

A favourite wrong statement: “In FB50 you can enter a vendor line by typing the vendor number.” No — FB50 is for G/L accounts only. Vendor and customer lines need the classic transactions (F-02 with keys 31/21/01/11, or the dedicated invoice transactions). If an exam option claims FB50 handles all account types, it is false.

10 Step by step — FB03: display & verify a document

Posting without verifying is typing blindfolded. FB03 — which you met for tracking in Lesson 3 — is how you prove your own entry.

  1. Type FB03. Enter the three-part document key: document number (100000123), company code (PK01), fiscal year (2026). Press Enter.
  2. The document overview opens: header on top (dates, type SA, reference, who entered it and when), every line below with account, debit/credit and amount.
  3. Verify like an auditor: Do the accounts match the voucher? Are debit and credit on the correct sides? Is the posting date in the intended period? Is the cost centre present on the expense line?
  4. Double-click any line to see its full detail — text, assignment, tax data, and the account assignments (cost centre / profit centre).
  5. Use the environment / follow-on options when needed: the same document can be reached from FBL3N by double-clicking its line — the drill-down path from Lesson 3 ends here.

Key term · Document key

A document is uniquely identified by three fields together: document number + company code + fiscal year (from Lesson 3). FB03, FB02 and FB08 all ask for the same three. The same number 100000123 can legally exist in another company code or another year — it would be a completely different document. Document number akela CNIC number nahi — us ke saath company code aur saal bhi chahiye, jaise naam ke saath walid ka naam.

11 FB02 — change a document: what you may and may not touch

Posted documents are almost — but not quite — carved in stone. FB02 lets you polish the words, never the numbers.

Open FB02 with the same document key (number + company code + fiscal year). SAP shows the document with a small set of fields open for editing. The rule behind it is the golden rule of accounting systems: anything that changes the accounting result is locked; anything that only explains it better can be changed.

You CAN change (FB02)

  • Header text and reference (if not already used as a clearing reference)
  • Line item text — fix a typo, add the cheque number
  • Assignment field on a line
  • Payment terms / payment method / house bank on vendor & customer lines
  • Document header’s “entered by” style data — no, not even this; only the explanation fields above

You can NEVER change

  • Amount — not one rupee
  • G/L account or posting key
  • Posting date — and therefore the period
  • Document type and company code
  • Cost centre and other account assignments on a posted line
  • Anything at all on a cleared item, or in a document that has already been reversed

So if you posted rent of 50,000 but the voucher says 55,000, FB02 cannot rescue you — the amount is locked. The professional path is: reverse the wrong document (FB08) and post a fresh, correct one. That is exactly the next section.

Analogy · Register par pen ki entry

FB02 aisa hai jaise register mein pen se likhi entry ke neeche note add karna — “cheque no. 8841 tha” likh sakte hain. Lekin rakam ya tareekh par pen pherna (overwrite) mana hai; woh ghalti ho to poori entry ko kaat kar (reversal) nayi entry likhi jati hai — aur kaati hui entry bhi parhi ja sakti hai. Audit trail kabhi nahi tootta.

12 FB08 — reversal: undoing a posting the legal way

SAP has no Delete button for posted documents — deliberately. A reversal cancels an entry by posting its exact mirror image.

Key term · Reversal

A reversal creates a new document whose every line is the opposite of the original: each debit becomes a credit and each credit becomes a debit, in the same amounts. The two documents together net to zero, and both stay in the books forever, linked to each other. Reversal = ghalti ko mitana nahi, us ke barabar ki ulti entry karke asar khatam karna — dono entries record mein rehti hain.

  1. Type FB08. Enter the document key: number, company code, fiscal year.
  2. Enter a Reversal reason — a small code explaining why (standard reasons: 01 reversal in current period, 02 reversal in closed period, 03 actual reversal in current period with negative postings where allowed). The reason also decides whether the reversal posts into the same period or the currently open one.
  3. Give the posting date for the reversal document (default: today / the original date, depending on the reason).
  4. Press Display before reversal if you want one last look, then Post. SAP creates the reversal document (standard type AB unless configured otherwise) and stamps the original with the reversal document’s number and date.
  5. Verify in FB03: the original now shows “Reversed with …” and the reversal document shows “Reversal of …”. Balances are back to where they were before the wrong entry.

Rules and neighbours of FB08 Exam favourite

  • One document at a time: FB08 reverses a single document. For many documents at once, the mass reversal transaction is F.80.
  • Cleared items block reversal: if a line of the document has already been cleared (e.g. the bank line matched in reconciliation), the clearing must be reset first (FBRA) — you cannot reverse a settled entry directly.
  • A reversal cannot itself be reversed in the ordinary way; and an already-reversed document cannot be reversed again. To “undo the undo”, post a fresh normal entry.
  • Closed period? If the original period is closed, choose a reversal reason / posting date that lands the reversal in an open period — the original document stays untouched in its closed period.
  • Documents from other modules (e.g. a goods receipt from MM or billing from SD) are reversed in their own module, not with FB08.

13 Park & hold — the two safety nets for unfinished work

Real life interrupts: a missing cost centre, a manager who must approve, a phone call mid-entry. SAP gives you two different ways to stop safely — and the exam tests the difference hard.

Parking, step by step (G/L)

  1. Open FV50 — it looks like FB50. Enter header and whatever lines you already know; the entry may stay unbalanced.
  2. Press Save as Parked. SAP assigns a real document number and confirms the document is parked.
  3. Later — by you or a colleague — open FBV0, give the document key, review / complete the lines until the balance is zero.
  4. Press Post in FBV0. Only now do balances move and the document becomes a normal posted document, keeping the number it received when parked.

Holding, step by step

  1. In FB50, halfway through an entry, press Hold. SAP asks for a temporary hold name — accept the suggestion or type your own.
  2. Close the screen safely. Nothing is posted, nothing is numbered.
  3. Return to FB50 and choose “Held document” retrieval: your draft re-opens exactly as you left it. Finish it and post normally — or delete the held draft if it is no longer needed.
Analogy · Park = file mein lagana, Hold = drawer mein rakhna

Park matlab adhoori file ko office file mein laga kar number de dena — koi doosra clerk ya officer bhi usay nikaal kar mukammal kar sakta hai. Hold matlab kagaz apne personal drawer mein rakhna — sirf aap hi usay wapas nikaal sakte hain, aur us par koi official number nahi laga.

Exam trap · “Parked documents update the ledger”

False — and it is asked constantly. A parked document has a number but no effect on balances, line items or reports until it is posted with FBV0. Likewise, a parked document can be deleted (FBV2 → delete) — unlike a posted one, which can only be reversed.

15 Exam traps

The statements C_TS4FI loves to test — each one is a trap that catches candidates who “almost” know this lesson.

Trap 1 · “A posted document can be deleted if it is wrong”

Never. Posted documents cannot be deleted or edited in their amounts/accounts. The only correction is a reversal (FB08) plus a fresh posting. Deletion exists only for parked documents (and held drafts).

Trap 2 · “In FB02 you can correct the amount”

FB02 changes only explanation fields — texts, reference, assignment, payment data on subledger lines. Amount, account, posting date, document type and cost centre are locked forever at posting time.

Trap 3 · “40 is credit, 50 is debit”

Reversed on purpose in options. Burn it in: 40 = Debit G/L, 50 = Credit G/L. (“Chaar-sau Debit, Pachaas Credit.”)

Trap 4 · “FB50 can post vendor and customer lines”

FB50 is G/L-only. Mixed documents with vendor/customer lines use classic transactions such as F-02 with posting keys 31 / 21 / 01 / 11, or the dedicated AP/AR transactions.

Trap 5 · “A parked document affects account balances”

It does not — parked documents are invisible to balances and reports until posted via FBV0. But they do already own a real document number, unlike held documents.

Trap 6 · “FB08 reverses many documents at once”

FB08 = exactly one document. Mass reversal is F.80. And a document whose items are already cleared cannot be reversed until the clearing is reset (FBRA).

Trap 7 · “Document number alone finds the document”

The document key is three parts: number + company code + fiscal year. FB03 / FB02 / FB08 all demand all three — the same number can exist elsewhere as a different document.

Trap 8 · “Posting date and document date do the same job”

The posting date decides period and fiscal year — and must fall in an open period. The document date is only the date on the source paper. Confusing them is a classic source of “period not open” errors.

16 A–Z glossary

Every technical term of this lesson, in one place, in simple words.

ACDOCA
The Universal Journal table in S/4HANA where every posted line item is stored. All balances and reports are built from its rows.
BKPF
The table holding document headers — one row per document (dates, type, company code, reference).
Clearing
Matching an open item with its settlement (invoice with payment) so both become “cleared”. Cleared items stay visible; they are never deleted.
Cost centre
An internal label showing where a cost belongs (department/branch). Required on expense lines when the field status group demands it.
Document
One complete, balanced accounting entry in SAP: one header + at least two line items, identified by number + company code + fiscal year.
Document type
Two-letter header code (SA, KR, KZ, DR, DZ, AB…) that classifies the entry and controls its number range and allowed account types. Defined in OBA7.
Enjoy transaction
SAP’s friendlier single-screen version of a classic transaction — FB50 is the Enjoy G/L posting screen.
F-02
Classic G/L posting transaction: header screen, then one screen per line, driven by posting keys.
F.80
Mass reversal — reverses many documents in one run (FB08 handles exactly one).
FB02
Change document: texts, reference, assignment and subledger payment data only. Amounts, accounts and dates are locked.
FB03
Display document — read-only view of one complete posted document.
FB08
Individual reversal of one posted document, using a reversal reason.
FB50
Enjoy G/L posting transaction: header and all lines on one screen, D/C column instead of posting keys, live balance light.
FBV0
Post a parked document — the step that turns a parked draft into a real posting with balance effect.
Field Status Group
Master-data setting (company code segment) deciding which fields are required / optional / hidden during posting to that account — e.g. cost centre required.
FS00
Central G/L account maintenance: display, create, change and extend G/L accounts (chart + company code segments together).
FV50
Park G/L document (Enjoy style); F-65 is the classic parking transaction.
Hold document
A personal, unnumbered draft saved inside FB50; only the same user can retrieve and finish it. No balance effect.
Line item
One row of a document: one account, one amount, debit or credit, plus text and assignments.
Line Item Display
Account-master tick that allows the account’s individual entries to be listed (FBL3N). Kept ON for almost all accounts.
Open Item Management
Account-master tick making entries stay “open” until cleared — for clearing accounts such as bank clearing or GR/IR.
Park document
An incomplete / unbalanced entry saved with a real document number but without any balance effect, completable and postable by another user (FBV0).
Posting
Saving a balanced entry into the books: it receives a document number, updates balances, and can afterwards only be reversed — never deleted.
Posting key
Two-digit code per line item controlling debit/credit and account type: 40 = Dr G/L, 50 = Cr G/L, 31 = Cr vendor, 21 = Dr vendor, 01 = Dr customer, 11 = Cr customer.
Posting date
The date that decides the posting period and fiscal year of a document; must fall in an open period (OB52).
Reversal
A new mirror-image document that cancels a posted document’s effect; both documents remain in the books, cross-referenced.
Reversal reason
Code given in FB08 explaining why a document is reversed; it also steers the reversal’s posting period behaviour.
Simulate
A no-save preview of the finished document before posting — the professional’s safety check.
SKA1 / SKB1
Tables of the two G/L master segments: SKA1 = chart of accounts segment, SKB1 = company code segment.

17 Summary — the whole lesson on one screen

If you remember one screen before the exam, make it this one.

  • FS00 maintains the G/L master centrally: chart segment (SKA1 — number, name, type, group, P&L/BS) + company code segment (SKB1 — currency, tax, field status group, line item display, open item management). Both must exist before posting.
  • A document = one header (BKPF) + line items (ACDOCA). Posting date decides period & year; the period must be open.
  • Posting keys: 40 = Dr G/L, 50 = Cr G/L. Document types: SA = general G/L document; types control number ranges (OBA7).
  • FB50 (Enjoy, G/L only, D/C column, live balance light) and F-02 (classic, posting keys, all account types) create identical documents. Always Simulate before Post.
  • FB03 displays; FB02 changes texts/reference/assignment only — never amount, account, date or cost centre.
  • FB08 reverses one document with a reversal reason, creating a mirror document (usually type AB). Mass reversal = F.80. Cleared items must be reset (FBRA) first. Posted documents are never deleted.
  • Park (FV50 → FBV0): real document number, unbalanced allowed, no balance effect, another user can post it. Hold (FB50): no number, personal draft, same user only.
  • Top errors: period not open (OB52), account not extended (FS00), required field from the field status group, unbalanced document, blocked account.
One-line memory chain

FS00 account banata hai · FB50 / F-02 entry karte hain · FB03 dikhata hai · FB02 lafz badalta hai · FB08 entry wapas leta hai · Park file mein, Hold drawer mein. — FS00 builds, FB50/F-02 post, FB03 shows, FB02 rewords, FB08 reverses; park is the office file, hold is your own drawer.
