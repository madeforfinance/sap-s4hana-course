03 Working practically — Customizing, saving & transports

Three ideas you must be clear on before any hands-on configuration work.

Reminder · Customizing (SPRO / IMG)

Customizing is the consultant’s workshop: the set of transactions where the system itself is set up — company codes defined, charts created, rules switched on. You enter it with T-code SPRO, which opens the IMG (Implementation Guide) — a tree of every setting in SAP. Most FI settings in this course live under Enterprise Structure and Financial Accounting Global Settings. Normal daily postings (invoices, payments) are not Customizing — they are application transactions like FB60 or F-02.

Customizing work (consultant)

  • Done in SPRO / direct IMG T-codes (OX02, OB13…)
  • Changes how the system behaves for everyone
  • Almost always asks for a transport request when saving
  • Done rarely, checked twice

Application work (end user)

  • Done in business T-codes (FB60, F-02, FS00…)
  • Creates business data — documents, master records
  • Saving creates a document / master record, no transport
  • Done daily, in large volumes
New term · Transport Request

When you save a Customizing change in a development system, SAP usually shows a pop-up: “Prompt for Customizing request”. A transport request is a numbered container (like a sealed parcel) that records your change so it can later be transported — moved in a controlled way — from Development to Quality to Production (the DEV → QAS → PRD journey from Lesson 2). Practical rule: if the pop-up appears, choose your existing request or create a new one with a clear description, and confirm. If you cancel the pop-up, the change is not saved.

Transport request woh dabba hai jisme aapki setting band ho kar agle system tak safar karti hai. Pop-up par Cancel dabana matlab setting save hi nahi hui.

The save-and-verify habit

  1. Enter the values carefully — read each field before typing.
  2. Save (Ctrl+S or the save icon) and handle the transport pop-up if it appears.
  3. Read the status bar — SAP confirms with a message like “Data was saved” or shows the request number. No message, no save.
  4. Go back and re-open the object. If your values are still there, the save is real. This 20-second check is what separates consultants from guessers.
Exam trap preview

Scenario questions love this sequence: “The consultant entered the settings but cancelled the transport request prompt. What is the result?” — the change was not saved. Saving Customizing and recording it in a transport request are one act, not two.

04 Company details — what exactly are we searching?

Segment 11:35 begins. First be precise: “company details” is two different objects, and mixing them is the classic beginner error.

When a manager says “show me the company details”, a beginner opens the first screen that says “company” and reads the wrong object. SAP has two company-like objects, and Lesson 5 separated them — here is the practical version:

Company — T-code OX15

  • 6-character ID, e.g. IBRA01
  • The consolidation unit: the legal group entity whose companies are combined for group reporting
  • Details are light: name, address, language, country, currency of the company
  • Stored in table T880 (global company data)
  • You do not post anything in a Company

Company Code — T-code OX02

  • 4-character ID, e.g. PK01 (field name BUKRS)
  • The legal accounting unit: the entity whose Balance Sheet and P&L are prepared
  • Details are rich: name, city, country, local currency, language, fiscal year variant link, chart assignment…
  • Stored in table T001
  • All FI postings happen inside a Company Code
Reminder · Company Code (BUKRS)

The company code is the smallest unit in SAP FI for which a complete, legally independent set of books is kept. Its 4-character key is called BUKRS in tables and on screens. When someone says “company details” in an FI context, nine times out of ten they mean the company code details in T001 — currency, country, language, fiscal year variant, and the assigned chart of accounts.

The detail fields you will be asked to verify

Field (screen)Technical nameWhat “correct” looks like — example
Company CodeBUKRSPK01 — 4 characters, never changeable after creation
Company NameBUTXTThe legal name as it should print on reports
City / CountryORT01 / LAND1e.g. Faisalabad / PK
CurrencyWAERSPKR — the local currency of the legal books (Lesson 7)
LanguageSPRASEN — language of the company code’s texts
Company (assignment)BUKRS → CompanyWhich 6-character Company this code reports up to

Beyond OX02, the company code’s global parameters (T-code OBY6) hold its working settings: chart of accounts, fiscal year variant, field status variant, posting period variant. A full “company details” check reads both screens — OX02 for identity, OBY6 for behaviour.

Analogy · CNIC card vs bank account form

The Company is like the family name on a CNIC — it identifies the household for government grouping. The Company Code is the full bank account form — your name, address, currency of the account, everything money actually moves through. Searching “company details” and opening only the family name is like verifying an account by reading only the surname.

05 Search tools — F4 help, wildcards & matchcodes

The three search skills every SAP screen rewards. Learn them once; use them ten thousand times.

New term · Search Help (F4 Help / Value Help)

Almost every input field in SAP has a hidden list of allowed values. Pressing F4 (or clicking the small search icon at the right of the field) opens that list — SAP calls it the search help or value help. Instead of guessing a code from memory, you search by name, filter, and double-click the right row; SAP copies the exact code into your field. F4 is the difference between “I think the code was PK01…” and knowing.

New term · Matchcode & Wildcards

The old SAP name for a search help is a matchcode — you will still meet the word in menus and exam questions; they mean the same family of search tools. Inside search fields you can use wildcards: the star * means “any characters, any number” and the plus + means “exactly one character”. So PK* finds PK01, PK02, PKH1… and *Trading* finds any name containing the word Trading.

You typeMeaningExample results
PK*Starts with PK, anything afterPK01 · PK02 · PK99
*Apparel*Contains “Apparel” anywhereIbrahim Apparel & Trading
PK+1PK, exactly one character, then 1PK01 · PKA1 (not PK1, not PK001)
*Everything — no restrictionThe full list (careful: can be long)

The F4 routine — practise until it is a reflex

  1. Click into the field (for example, Company Code).
  2. Press F4. The search help pop-up opens — often with several tabs (by code, by name, by country…).
  3. Type your restriction with wildcards, e.g. name *Apparel*, and press Enter / the green tick.
  4. Read the result list carefully — code and name — then double-click the correct row.
  5. Confirm the field now holds the exact code before you press Enter on the main screen.

06 Step by step — finding company & company code details (OX02 · OX15)

The full practical routine, exactly as you would perform it on a training system.

Route A — Company code details via OX02

  1. In the command field, type OX02 and press Enter. (Menu path if you prefer: SPRO → Enterprise Structure → Definition → Financial Accounting → Edit, Copy, Delete, Check Company Code.)
  2. Choose Edit Company Code data. A list of all company codes appears — this list itself is your first search result.
  3. Use the Position / Find button (binoculars icon) or scroll: enter PK01 to jump straight to the row.
  4. Double-click the PK01 row. The detail screen opens: name, city, country, currency, language.
  5. Read every field against your checklist (§4). Note the Company field — the 6-character consolidation company this code belongs to.
  6. Press Back (F3) — you changed nothing, so no save is needed. Viewing is free; only editing creates responsibility.

Route B — Company details via OX15

  1. Type OX15 in the command field, Enter. (Menu path: SPRO → Enterprise Structure → Definition → Financial Accounting → Define Company.)
  2. The list of Companies (table T880) opens. Find IBRA01 with Position/Find or F4-style searching.
  3. Double-click to read: company name, address, country, language, and the company’s currency.
  4. Compare with OX02: same group, different object. The company code PK01 points up to company IBRA01 — that one field is the bridge between daily books and group reporting.

Route C — The 10-second route (when you already know the code)

Many display transactions ask for a company code at entry. Type the code, press F4 if unsure, Enter — and the header of the next screen (or Environment → Company Code data in some transactions) confirms the name and currency before you post anything. Checking the company code before posting is a professional habit: a posting in the wrong company code is one of the most expensive beginner mistakes, because documents cannot simply be “moved” afterwards.

Exam trap preview

“Which transaction shows the definition of a company code?” — OX02. “And of a company (consolidation)?” — OX15. The exam also swaps their tables on purpose: company code = T001, company = T880. OX02–T001, OX15–T880 — pin this pair down today.

New term · Session (Mode)

A session (SAP GUI calls it a mode) is one open SAP window with its own screen journey. You may have several sessions open at once — one showing the company code list, another the chart — and /o is how you spawn a new one without losing your place. Unsaved work lives only in its own session: closing a session throws its unsaved screen away, which is why /n inside a screen with unsaved changes asks before discarding.

Session matlab aik khuli hui SAP window. /o se nayi window khulti hai, purani waisi ki waisi rehti hai — aik par list, dusri par detail.

Favourites — your personal menu

On the SAP Easy Access screen you can build a Favourites list: right-click Favorites → Insert Transaction, type the T-code, and it stays one double-click away forever. A practical starter set for this course: OX02 · OX15 · OB13 · OBD4 · FS00 · SE16N · FB50 · F-02. Favourites are stored per user — they are your own desk drawers inside SAP.

Memory trick · “Slash wale teen dost”

/n = nayi transaction, purani khatam. /o = one more window. /nEND = din khatam, ghar jao. Three slashes, three speeds of leaving — pick the right one and you never lose work or waste a click.

Exam trap preview

“A user wants to open a second transaction without losing the current screen.” The answer is /oXXXX — new session. /nXXXX is the tempting wrong answer: it works, but it ends the current transaction first.

08 Checking the table behind the screen — T001 in SE16N

A consultant’s X-ray: when a screen is slow or a value is in doubt, look at the table itself.

Reminder · SE16N — General Table Display

SE16N is SAP’s general table display transaction: type a table name, set selection filters, and read the raw rows exactly as stored in the database. It changes nothing — it is a viewing window, not an editing tool. Every Customizing screen you use is simply a friendly face on top of a table; SE16N lets you verify what the face is showing.

Verifying company code PK01 in T001 — step by step

  1. Command field: /nSE16N, Enter.
  2. Table: type T001, Enter — the selection screen appears with T001’s fields.
  3. In the BUKRS (Company Code) field, enter PK01. Press F4 there if you want the search help — it works here too.
  4. Press F8 (Execute). Exactly one row returns: PK01’s stored truth.
  5. Compare the columns — BUTXT (name), LAND1 (country), WAERS (currency), SPRAS (language) — with what OX02 showed. They must agree; the screen reads this row.
  6. Exit with F3. You have verified the detail at database level — the strongest check a beginner can do.

Analogy · Showroom vs godown register

OX02 is the showroom — clean, arranged, customer-friendly. T001 in SE16N is the godown (warehouse) register — the raw stock book the showroom is stocked from. When the showroom display looks wrong, a smart shopkeeper checks the register, not the display. Screens can confuse; the table is the record.

Exam trap preview

Two favourites: (1) SE16N is for displaying table contents — it is not how you maintain Customizing (that is the IMG transaction, e.g. OX02). (2) If OX02 and T001 ever seem to disagree, trust neither blindly — you are probably looking at different clients or a different company code row. Check the client and the BUKRS filter first.

09 Chart of Accounts revision — the 5-minute recap

Segment 16:04 begins. Before setting anything, reload Lesson 7’s chart knowledge in practical form.

Reminder · Chart of Accounts (CoA)

A Chart of Accounts is the complete list of G/L accounts a company may post to — Cash, Bank, Sales, Rent, and every other khata. It is defined once in OB13 (table T004, 4-character key, technical field KTOPL), and assigned to company codes in OB62. An account that is not in the chart does not exist for posting — exactly like a register with no page for that khata.

  • One operating chart per company code — but one chart can serve many company codes, even across countries and currencies.
  • Three chart roles: operating (daily posting), group (linked per account by the group account number, in the chart segment SKA1), country (linked by the alternative account number, in the company code segment SKB1). Nobody posts in group or country charts.
  • Every G/L account has two segments: chart segment (SKA1, created once per chart) + company code segment (SKB1, once per company code). Both must exist before posting; maintained together in FS00.
  • Account groups (OBD4, table T077S) organise the chart into categories — and they are where today’s series lives (§11).
Memory trick · “List, Lambaai, Line”

Chart banane ke teen L: List (OB13 — chart exists), Lambaai (length — numbers kitne digits ke honge), Line (series — har group ki line/range kahan se kahan tak). Teeno L pure hon to chart tayyar hai.

10 Account-number length — the chart’s one big decision (OB13)

Set once per chart, felt in every account number forever after. Understand it fully before touching it.

New term · Length of G/L Account Number

When a chart is defined in OB13, one field — Length of G/L account number — fixes how many digits account numbers in this chart may have, from 1 up to a maximum of 10 digits. It is a property of the chart, not of any single account: choose 6, and every account number in that chart is up to 6 digits (100000, 400000, 501010…). Choose 10, and numbers may run to 10 digits. SAP stores shorter entries with leading zeros where needed, so the length is about capacity and structure, not about typing zeros.

How to choose — the practical reasoning

LengthCapacityFits which business?
4Up to 9,999 numbersVery small chart — quickly outgrown
6Up to 999,999The common practical choice: roomy series per group, numbers still easy to read and dictate on the phone
8Up to 99,999,999Large groups encoding extra meaning (entity / sub-ledger digits) in the number
10Maximum SAP allowsVery large or heavily structured charts — power that most companies never need

Two forces pull in opposite directions. Too short and your series (§11) run out of room — a growing company cannot fit new revenue accounts into a full range. Too long and every human who types, reads, or dictates an account number pays for digits that carry no meaning. Six digits with a clean series plan is the balance most mid-size companies choose — and it is the plan §13 builds.

Exam trap preview

Three traps live here. (1) Length is defined per chart of accounts (OB13) — not per company code and not per account. (2) The maximum length is 10 digits — any answer saying 8 or 12 as the SAP maximum is wrong. (3) Once G/L accounts exist in the chart, the length can no longer simply be shortened — the decision is effectively a before-you-create-accounts decision, like the company code currency in Lesson 7.

Analogy · Mobile number ki length

A country fixes its mobile numbers at 11 digits before issuing a single SIM — because every later system (billing, directories, apps) is built on that length. The chart’s account-number length is the same founding decision: fix it first, design the series inside it, and only then start “issuing SIMs” — creating accounts.

11 The “series” — account groups & number ranges (OBD4)

“Series” is the word practitioners use for the number ranges of the chart. Here is exactly what it means in SAP.

New term · Series (Account Group Number Range)

In everyday SAP project language, the series of a chart means the set of number intervals that divide the chart’s numbers among its account groups. Technically, each account group (defined per chart in OBD4, table T077S) carries two fields — From Account and To Account — and together all the groups’ intervals form the chart’s series plan: Assets own 100000–199999, Revenue owns 400000–499999, and so on. When a consultant says “set the series”, they mean: open OBD4 and give every account group its correct from–to interval.

Series matlab numberon ki taqseem — kis group ko kaunsi range milegi. 1xxxxx assets ki gali, 4xxxxx revenue ki gali; ghar (account) usi gali mein bane ga jiska woh hai.

The rules the system enforces

  • Every G/L account must belong to exactly one account group — the group field is compulsory in the account’s chart segment (SKA1).
  • The account number must fall inside its group’s interval. Create account 450000 in group REVN (400000–499999): accepted. Try to create it in group ASST (100000–199999): SAP refuses — the number is outside the group’s series.
  • Intervals of different groups in the same chart must not overlap. If ASST claims 100000–199999, no other group in that chart may claim any part of it. Overlap = two owners for one number = forbidden.
  • Gaps are allowed and wise. Leaving empty space between series (e.g. Assets end at 199999, Liabilities start at 200000, but within Assets you use only up to 150000) gives the business room to grow without renumbering.
  • The interval must fit the chart’s length. In a 6-digit chart, an interval ending at 1000000 (7 digits) is impossible — series design always starts from the length decision (§10).

Job 2 of the account group — do not forget it

From Lesson 7, remember the account group’s second job: it also carries the field status for the account master-data screen — while an account of this group is being created, which master fields are required, optional, or suppressed. The series is job 1; the master-data field status is job 2. Exam questions test both, and test that you do not confuse this with the posting field status group (OBC4), which is a different object entirely.

Analogy · Sheher ki gali numbering

A planned city gives each mohalla a number series: Block A houses are 1–99, Block B are 100–199. An address tells you the block before you read the nameplate — and the town planner forbids two blocks from claiming the same numbers. Account groups are the blocks; the series is the planner’s map; an account number is the house address that must sit in its own block.

12 Step by step — setting the series & length, and saving (OB13 · OBD4)

The complete hands-on sequence of segment 16:04 – 24:47, in the order a consultant performs it.

Part A — Create / check the chart and set its length (OB13)

  1. Command field: /nOB13, Enter. (Menu path: SPRO → Financial Accounting → General Ledger Accounting → Master Data → G/L Accounts → Preparations → Edit Chart of Accounts List.) The list of charts (table T004) opens.
  2. To check an existing chart: find it with Position/Find, double-click, and read the Length of G/L account number field. To create: choose New Entries.
  3. Enter the Chart of Accounts key (4 characters, e.g. IACO) and a clear description.
  4. Set Length of G/L account number = 6 — the decision from §10, made before any account exists.
  5. If the group uses one, enter the Group chart of accounts key; leave the chart unblocked only when the setup is complete (a blocked chart cannot receive accounts — a safety lock while building).
  6. Save (Ctrl+S). Handle the transport request pop-up (§3): select or create the request, confirm, and read the status-bar confirmation.

Part B — Set the series: account groups with their intervals (OBD4)

  1. Command field: /nOBD4, Enter. (Menu path: SPRO → … → G/L Accounts → Preparations → Define Account Group.)
  2. The list shows account groups per chart — first make sure you are looking at rows for your chart (IACO). Working in the wrong chart’s groups is the most common OBD4 accident.
  3. Choose New Entries for each group you need. For every group enter: Chart, Account Group key (4 characters), Description, From Account, To Account — the series interval.
  4. Enter the full plan (§13 gives one): ASST 100000–199999, LIAB 200000–299999, EQUT 300000–399999, REVN 400000–499999, EXPN 500000–599999, plus a tighter CASH sub-range if your design uses one.
  5. Double-check before saving: no overlaps, every interval inside the 6-digit length, sensible gaps left inside each range.
  6. Save (Ctrl+S), confirm the transport request, read the confirmation message.
  7. Verify (§3 habit): exit, re-enter OBD4, filter your chart, and read the intervals back. Then — the real proof — create a test account in FS00 inside one interval (accepted) and try one outside its group’s interval (refused). The system itself confirms your series.

13 Worked example — a complete series plan for a trading company

One full design, from length decision to the last interval — the pattern you can reuse in the exam and on a project.

The business. A Pakistani apparel trading company (company code PK01, local currency PKR) is implementing SAP. It needs the normal trading accounts: cash and banks, receivables control, inventory, fixed assets, payables control, loans, owner’s capital, sales (domestic and export), purchases / cost of sales, and operating expenses.

Decision 1 — Length (OB13): 6 digits. Capacity is far beyond the company’s needs, numbers stay short enough to read aloud, and the first digit can carry the series meaning.

Decision 2 — Series (OBD4): the first digit names the family — a design habit called speaking numbers, because the number itself speaks: any 4xxxxx is revenue before you read its name.

Account groupSeries (From – To)Example accounts that will live here
ASST — Assets100000 – 199999110000 Cash · 111000 Bank · 120000 Trade Receivables (recon.) · 130000 Inventory · 150000 Fixed Assets
LIAB — Liabilities200000 – 299999210000 Trade Payables (recon.) · 220000 Bank Loans · 230000 Accrued Expenses
EQUT — Equity300000 – 399999300000 Share Capital · 310000 Retained Earnings

Reading the plan like a consultant

  • Balance sheet first, P&L after: 1–3 are Balance Sheet families, 4–5 are P&L families — the number order mirrors the financial statements themselves.
  • Reconciliation accounts sit inside their family: receivables control (120000) inside Assets, payables control (210000) inside Liabilities — the series respects accounting logic, not alphabet.
  • Room to grow: each family holds 100,000 numbers; the company uses a few dozen. Growth never forces renumbering.
  • The proof test: creating 450000 “Sales — Online” in REVN succeeds (inside 400000–499999); creating it in ASST fails — the series is enforced by the system, not by a policy document.
Analogy · Phone number ka area code

14 Exam traps

The mistakes C_TS4FI questions are designed to catch in this lesson’s topics. Read these twice.

  • Trap 1 — “Company and company code are the same object.” No. Company (OX15, 6 characters, table T880) is the consolidation unit; Company Code (OX02, 4 characters, field BUKRS, table T001) is the legal accounting unit you post in.
  • Trap 2 — “The user does not know the code, so a report must be run.” The everyday answer is the search help — F4 — with wildcards (* any number of characters, + exactly one). “Matchcode” is the older name for the same search idea.
  • Trap 3 — “/nOB13 keeps the current transaction open.” /n ends the current transaction. To keep it and open a new window, use /oOB13 — a new session.
  • Trap 4 — “SE16N is used to maintain company code data.” SE16N only displays tables (e.g. T001). Maintenance happens in the Customizing transaction (OX02). Display ≠ maintain.
  • Trap 5 — “Account-number length is set per company code / per account.” It is set per chart of accounts in OB13, maximum 10 digits, and is decided before accounts are created.
  • Trap 6 — “Two account groups may share part of a number range.” Intervals in one chart must never overlap; gaps are fine, overlaps are rejected by design.
  • Trap 7 — “An account number may sit outside its group’s range if the name matches.” The system checks the number against the group’s From–To interval (OBD4), not the name. Outside the series = creation refused.
  • Trap 8 — “Account group and field status group are the same.” Account group (OBD4) = number series + master-data screen field status. Field status group (OBC4) = posting screen field status. Different objects, different jobs — carried from Lesson 7, still examined.
  • Trap 9 — “Cancelling the transport prompt still saves the setting.” It does not. A Customizing change saved without its transport request is not saved at all in a system that requires the prompt.
  • Trap 10 — “One chart per company code is required.” One operating chart can serve many company codes; each company code has exactly one operating chart. The series and length then apply to every company code sharing that chart.

15 A–Z glossary

Every technical term from this lesson, in one line each.

Account Group (OBD4)
Category of G/L accounts inside a chart; carries the number series (From–To interval) and the master-data screen field status. Table T077S.
BUKRS
Technical field name of the company code (4 characters) in tables and on screens.
Chart of Accounts
The complete list of G/L accounts; 4-character key, field KTOPL, table T004; defined in OB13, assigned in OB62.
Company (OX15)
The 6-character consolidation unit a company code reports up to; stored in table T880. No postings happen in a Company.
Company Code (OX02)
The 4-character legal accounting unit whose books are kept; stored in table T001; all FI postings happen inside it.
Command Field
The input box at the top-left of the SAP GUI screen where T-codes and slash commands (/n, /o) are typed.
Customizing (SPRO / IMG)
The consultant’s setup area of SAP; SPRO opens the Implementation Guide (IMG) tree of all settings.
F1 / F4
F1 = field help (explains the field under the cursor). F4 = search help (list of allowed values for the field).
Favourites
A user’s personal list of transactions on the SAP Easy Access screen for one-click access.
Global Parameters (OBY6)
The company code’s working settings: chart of accounts, fiscal year variant, field status variant, posting period variant.
Length of G/L Account Number
Chart-level setting in OB13 fixing how many digits account numbers may have; maximum 10; decided before accounts are created.
Matchcode
The older SAP name for a search help — a structured search over allowed values.
OB13 / OBD4 / OB62
Define chart of accounts (and its length) / define account groups and their series / assign the chart to a company code.
OX02 / OX15
Define & display company codes (T001) / define & display companies (T880).
SE16N
General Table Display — view any table’s rows (display only, never maintenance).
Series
Practical name for the set of number intervals (From Account – To Account) that account groups divide a chart’s numbers into; set in OBD4.
Session (Mode)
One open SAP GUI window with its own screen journey; /o opens a new session, /i closes the current one.
Slash Commands
/nXXXX end current transaction, open XXXX · /oXXXX open XXXX in a new session · /n return to menu · /nEND log off with confirmation.
Transport Request
The numbered container that records a Customizing change for controlled movement DEV → QAS → PRD; cancelling its prompt means the change is not saved.
Wildcard
Search pattern character: * = any characters, any number; + = exactly one character.

16 Summary — the whole lesson on one screen

  • Part 2 = practical revision: for every topic the loop is Find it → Open it → Read every field → Change or confirm → Save → Re-open and verify. A setting that is not saved — including its transport request — does not exist.
  • Company details: Company = 6-character consolidation unit, OX15, table T880. Company Code = 4-character legal accounting unit (BUKRS), OX02, table T001 — name, city, country, currency (WAERS), language, and the Company it reports to. Working settings live in the global parameters, OBY6.
  • Searching: F4 opens the search help (matchcode) on almost any field; wildcards * (any number of characters) and + (exactly one) make name searches like *Apparel* possible. SE16N verifies the same data at table level — display only.
  • Shortcuts: /nXXXX switch transaction (current ends), /oXXXX new session (current survives), /n back to menu, /nEND log off safely, Ctrl+/ jump to the command field, F1 field help, F4 value help, Ctrl+S save. Favourites pin your daily T-codes to the Easy Access screen.
  • Chart of Accounts: defined in OB13 (table T004), assigned in OB62; exactly one operating chart per company code, shareable by many company codes.
  • Length: the chart’s Length of G/L account number (OB13) fixes the digits of every account number — maximum 10, practically often 6 — and is decided before accounts are created.
  • Series: each account group (OBD4, table T077S) owns a From–To interval; all intervals together are the chart’s series. Rules: every account belongs to one group, its number must sit inside the group’s interval, intervals never overlap, gaps are allowed and wise, and everything must fit the chart’s length. Save with Ctrl+S, confirm the transport request, then re-open and prove it with a test account in FS00.
